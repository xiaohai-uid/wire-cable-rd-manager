# 05 — 产品与测试模板管理

**What to build:** 维护产品（型号、名称、图纸编号、说明）和每个产品的测试模板
（测试项、规格、排序）。测试模板是批次录入的起点 —— 它决定网格铺出多少行、每行规格是什么。

本工单最重要的一条不是 CRUD，而是：**编辑模板时实时显示每条规格被解析成了什么判定规则。**
研发工程师在录数据之前就能看到「系统把 `≥20dB` 读成了 min / 阈值 20 / 单位 dB」，
或者看到「这条规格无法识别」。这把规格错误的发现时点从「判定出错之后」提前到「写规格的当时」。

删除产品必须级联清掉它的测试台账和测试模板 ——
1.0 版漏了 `PRAGMA foreign_keys = ON`，留下了查不到归属的孤儿记录。
删除前要显示将被一并删除的数据条数。

**Blocked by:** 02 — 质量热力图首页（只需要 `DataPort` 接口存在，与 03/04 可并行）

**Status:** ready-for-agent

- [ ] 产品列表、新增、编辑、删除可用
- [ ] 测试模板可按产品编辑：增删测试项、改规格、调整排序
- [ ] 编辑规格时实时显示解析出的判定规则（种类 + 阈值 + 单位）
- [ ] 规格无法识别时当场明确提示，不允许静默保存成一个会错判的规格
- [ ] 支持把一个产品的测试模板整体复制到另一个产品
- [ ] 删除产品前显示将被级联删除的测试台账与模板条数
- [ ] 删除产品后不留下任何孤儿测试台账记录
- [ ] 所有写操作失败时给出明确错误信息，不静默失败
